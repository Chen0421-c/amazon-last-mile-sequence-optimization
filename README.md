# Road Freight Delivery Sequence Optimization using Machine Learning

This repository supports the final experiment pipeline for the master's dissertation project:

**Road Freight Delivery Sequence Optimization Using Machine Learning**

The project uses the **Amazon Last Mile Routing Research Challenge** dataset to learn driver-like next-stop preference from historical driver-executed routes and integrate the learned preference signal into a hybrid route-generation framework.

## Final research objective

The goal is not to produce the shortest possible route only. The final dissertation experiment studies whether a machine-learning-enhanced hybrid route-generation method can balance:

- operational efficiency, measured mainly by travel-time ratio to the actual driver route;
- driver-like routing behaviour, measured by LCS similarity, position match ratio, same-zone continuity, and zone-change reduction.

The final hybrid cost is:

```text
cost(i,j) =
  alpha * travel_time_norm(i,j)
+ beta  * (1 - ML_preference_probability(i,j))
+ gamma * zone_penalty(i,j)
+ delta * time_window_risk(j)
+ eta   * service_package_penalty(j)
```

The validation-selected final weights are:

```text
travel_weight      = 0.70
preference_weight  = 0.15
zone_weight        = 0.15
time_window_weight = 0.00
workload_weight    = 0.00
weight_id          = w000091
```

The zero weights for the time-window and workload proxy terms should not be interpreted as evidence that these real-world constraints are theoretically irrelevant. They mean that, under the current proxy definitions and validation objective, these terms did not provide additional route-level benefit beyond travel time, learned preference, and zone continuity.

## Main final results

### Pairwise sample generation

Full pairwise samples were generated from all complete-route splits:

```text
train:      4,240,455 rows, 5,009 routes
validation: 899,583 rows, 1,073 routes
test:       914,796 rows, 1,073 routes
```

Each decision context contains exactly one positive next-stop sample.

### Preference model selection

The final top-3 full-scale model comparison used XGBoost, LightGBM, and CatBoost. CatBoost achieved the best validation sampled top-1 accuracy and was selected as the final preference model:

```text
CatBoost validation sampled_top1_accuracy = 0.9223
CatBoost test sampled_top1_accuracy       = 0.9245
```

### Hybrid route generation

The final validation-selected hybrid weights were:

```text
travel=0.70, preference=0.15, zone=0.15, time_window=0.00, workload=0.00
```

Final route generation compared:

```text
travel_time_nearest_neighbor
preference_greedy
hybrid_greedy_best_weight
```

The final test-set interpretation is a trade-off:

- Travel-time nearest neighbour has the lowest pure travel-time ratio.
- Hybrid greedy best weight slightly increases travel-time ratio compared with travel-time nearest neighbour.
- Hybrid greedy best weight substantially improves driver-like route behaviour, especially same-zone ratio and zone-change reduction.
- Hybrid greedy best weight strongly outperforms preference-only greedy in travel-time efficiency while also improving route-similarity metrics.

## What is not implemented

The following items are **not** part of the final completed experiment and should be discussed only as future work or optional extensions:

- Beam Search route generation;
- OR-Tools routing baseline;
- TabPFN comparison;
- MCTS rollout;
- multi-seed repeated robustness trials;
- Hugging Face Space / Streamlit UAT deployment demo.

The final statistical analysis uses paired route-level tests, Wilcoxon tests where available, bootstrap confidence intervals, and paired effect sizes. Welch t-test is not the main method because the final route-level method comparison is paired on the same routes.

## Final dissertation framing

The final contribution should be described as a reproducible, data-driven, stop-level preference-learning and hybrid route-generation framework. The main finding is not that the hybrid method minimizes travel time better than a travel-time-only heuristic. Instead, the hybrid method provides a better balance between operational efficiency and driver-like route structure by preserving much stronger zone continuity and reducing zone changes while keeping travel-time ratio close to the travel-time nearest-neighbour baseline.
